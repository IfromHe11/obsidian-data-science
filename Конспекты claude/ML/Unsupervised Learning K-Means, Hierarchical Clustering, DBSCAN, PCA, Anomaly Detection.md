# Введение в Unsupervised Learning

Напомним из Части 1: в unsupervised learning **нет** размеченных ответов $y$ — есть только признаки $X$, и модель сама ищет структуру в данных. Три основные подзадачи:

- **Clustering (кластеризация)** — разбить объекты на группы (кластеры) так, чтобы объекты внутри группы были похожи друг на друга, а объекты из разных групп — различались.
- **Dimensionality reduction (снижение размерности)** — сжать данные с большим числом признаков в меньшее число новых признаков, сохранив максимум полезной информации.
- **Anomaly detection (поиск аномалий)** — найти объекты, существенно отличающиеся от общей массы данных.

# K-Means

## 1. Что решает алгоритм

K-Means решает задачу кластеризации: разбивает $n$ объектов на заранее заданное число $K$ кластеров, минимизируя разброс объектов внутри каждого кластера.

## 2. Интуиция

Представьте, что нужно разместить $K$ пунктов выдачи заказов в городе так, чтобы суммарное расстояние, которое проезжают клиенты, было минимальным. Логичная стратегия: (1) расставить пункты как-то для начала, (2) прикрепить каждого клиента к ближайшему пункту, (3) передвинуть каждый пункт в "центр тяжести" всех прикреплённых к нему клиентов, (4) повторить шаги 2-3, пока пункты не перестанут заметно двигаться. K-Means делает ровно это.

## 3. Математическая идея

### Centroid (центроид)

Центроид кластера — это просто **среднее (среднее арифметическое по каждому признаку)** всех объектов, принадлежащих этому кластеру. Это не реальный объект из датасета, а "воображаемая" точка — центр масс кластера.

### Objective function (целевая функция)

K-Means минимизирует суммарное квадратичное отклонение объектов от центроида своего кластера, часто называемое **inertia** или **WCSS (Within-Cluster Sum of Squares)**:

$$J = \sum_{i=1}^{n} |x_i - \mu_{c_i}|^2$$

**Разбор:**

- $x_i$ — вектор признаков объекта $i$.
- $c_i$ — номер кластера, к которому отнесён объект $i$.
- $\mu_{c_i}$ — центроид кластера $c_i$.
- $|x_i - \mu_{c_i}|^2$ — квадрат евклидова расстояния от объекта до центроида его кластера (та самая норма из Части 1).
- Сумма по всем объектам даёт общую "рыхлость" всех кластеров одновременно — чем меньше $J$, тем плотнее и компактнее кластеры.

## 4. Как алгоритм работает (пошагово)

1. **Инициализация:** выбрать $K$ начальных центроидов (случайно или через K-Means++, см. ниже).
2. **Assignment step (шаг присвоения):** каждый объект относится к кластеру с ближайшим (по евклидову расстоянию) центроидом.
3. **Update step (шаг обновления):** для каждого кластера пересчитать центроид как среднее всех объектов, отнесённых к нему на предыдущем шаге.
4. Повторять шаги 2–3, пока центроиды не перестанут заметно меняться (сходимость) или не будет достигнуто максимальное число итераций.

Это **итеративный алгоритм оптимизации**, похожий по духу на Gradient Descent из Части 1: на каждом шаге целевая функция $J$ гарантированно не возрастает, и алгоритм сходится к (локальному) минимуму.

## 5. Разбор алгоритма пошагово на небольшом датасете

Датасет из 4 точек (два признака), $K=2$:

|Объект|x|y|
|---|---|---|
|A|1|1|
|B|1.5|2|
|C|8|8|
|D|9|9|

**Инициализация:** выберем начальные центроиды $\mu_1 = A(1,1)$, $\mu_2 = C(8,8)$.

**Итерация 1 — Assignment:**

- A: расстояние до $\mu_1$ = 0, до $\mu_2$ = $\sqrt{49+49}\approx9.9$ → кластер 1
- B: до $\mu_1$ = $\sqrt{0.25+1}\approx1.1$, до $\mu_2 \approx\sqrt{42.25+36}\approx8.8$ → кластер 1
- C: до $\mu_1\approx9.9$, до $\mu_2$=0 → кластер 2
- D: до $\mu_1\approx11.3$, до $\mu_2\approx1.4$ → кластер 2

**Итерация 1 — Update:**

- Новый $\mu_1$ = среднее A и B = $\left(\frac{1+1.5}{2}, \frac{1+2}{2}\right) = (1.25, 1.5)$
- Новый $\mu_2$ = среднее C и D = $\left(\frac{8+9}{2}, \frac{8+9}{2}\right) = (8.5, 8.5)$

**Итерация 2 — Assignment:** пересчитываем расстояния с новыми центроидами — распределение объектов не меняется (A, B по-прежнему ближе к $\mu_1$; C, D — к $\mu_2$).

Так как назначения кластеров не изменились, алгоритм **сошёлся**. Итоговые кластеры: {A, B} и {C, D} — интуитивно логичный результат для этих данных.

## Выбор K

### Elbow Method (метод локтя)

Строится график зависимости inertia ($J$) от числа кластеров $K$. С ростом $K$ inertia всегда убывает (при $K=n$ она равна нулю — каждый объект в своём кластере). Но на графике обычно виден "изгиб" ("локоть") — точка, после которой добавление новых кластеров даёт всё меньший прирост качества. Эта точка — разумный кандидат на оптимальное $K$.

### Silhouette Score (силуэтный коэффициент)

Для каждого объекта считается, насколько он близок к своему кластеру по сравнению с ближайшим соседним кластером. Значение от $-1$ до $1$: близко к 1 — объект хорошо соответствует своему кластеру и далёк от соседних; около 0 — объект на границе между кластерами; отрицательное — объект, вероятно, отнесён не в тот кластер. Усреднённый по всем объектам Silhouette Score позволяет численно сравнивать качество кластеризации при разных $K$ — в отличие от Elbow Method, не требует визуальной оценки "на глаз".

### Random initialization и K-Means++

**Проблема:** случайная инициализация центроидов может привести к плохой сходимости (застревание в неудачном локальном минимуме), а разные случайные инициализации дают разные итоговые кластеры.

**K-Means++** — более умная стратегия инициализации: первый центроид выбирается случайно, а каждый следующий выбирается **с вероятностью, пропорциональной квадрату расстояния** до ближайшего уже выбранного центроида — то есть новые центроиды с большей вероятностью попадают далеко от уже выбранных, что даёт более равномерное, разумное начальное покрытие пространства данных и заметно улучшает итоговое качество кластеризации по сравнению с чисто случайной инициализацией.

> **Типичная ошибка новичка.** Запускать K-Means лишь один раз со случайной инициализацией. На практике (и по умолчанию в sklearn) алгоритм запускается несколько раз с разными инициализациями (`n_init`), и выбирается запуск с наименьшей итоговой inertia.

## Python

```python
from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler
import numpy as np

X = np.array([[1,1],[1.5,2],[8,8],[9,9]])

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)  # масштабирование важно, K-Means основан на расстояниях

model = KMeans(n_clusters=2, init="k-means++", n_init=10, random_state=42)
labels = model.fit_predict(X_scaled)

print("Метки кластеров:", labels)
print("Центроиды:", model.cluster_centers_)
print("Inertia:", model.inertia_)

# Elbow method
inertias = []
for k in range(1, 5):
    km = KMeans(n_clusters=k, n_init=10, random_state=42).fit(X_scaled)
    inertias.append(km.inertia_)
print(inertias)
```

## Важные гиперпараметры

|Параметр|Значение|Эффект|
|---|---|---|
|`n_clusters` (K)|Число кластеров|Главный гиперпараметр, подбирается через Elbow/Silhouette|
|`init`|Стратегия инициализации|`k-means++` почти всегда лучше `random`|
|`n_init`|Число запусков с разной инициализацией|Больше → устойчивее итоговый результат, но дольше|
|`max_iter`|Максимум итераций одного запуска|Обычно 300 достаточно для сходимости|

## Плюсы / Минусы / Когда использовать

**Плюсы:** простой и быстрый алгоритм, хорошо масштабируется на большие датасеты, легко интерпретировать через центроиды.

**Минусы:** нужно заранее задавать $K$; предполагает кластеры **выпуклой, примерно сферической формы** одинакового размера — плохо работает с кластерами сложной формы или сильно различающейся плотности; чувствителен к выбросам (выброс сильно "тянет" центроид на себя); чувствителен к масштабу признаков.

**Когда использовать:** сегментация клиентов, группировка похожих объектов, когда кластеры примерно сферической формы и вы можете разумно оценить $K$.

**Когда НЕ использовать:** кластеры сложной, вытянутой или вложенной формы (см. DBSCAN ниже), сильно разное число объектов/плотность в разных группах, много выбросов.

# Hierarchical Clustering (Иерархическая кластеризация)

## Интуиция

Вместо того чтобы сразу делить данные на $K$ кластеров, иерархическая кластеризация строит **дерево вложенных кластеризаций** — от каждого объекта как отдельного кластера до одного большого кластера, содержащего все объекты (или наоборот). Итоговое число кластеров можно выбрать уже после построения дерева, просто "разрезав" его на нужном уровне.

## Agglomerative vs Divisive

**Agglomerative clustering (агломеративная, снизу вверх)** — наиболее распространённый подход: начинаем с того, что каждый объект — свой собственный кластер, затем на каждом шаге объединяем два **самых близких** кластера в один, пока не останется один кластер, содержащий все объекты.

**Divisive clustering (дивизивная, сверху вниз)** — обратный подход: начинаем с одного кластера, содержащего все объекты, и на каждом шаге разбиваем его на более мелкие. Используется значительно реже из-за большей вычислительной сложности.

## Dendrogram (дендрограмма)

Результат агломеративной кластеризации визуализируется в виде дерева (дендрограммы), где по горизонтали — объекты, по вертикали — расстояние, на котором произошло объединение кластеров. Чтобы получить конкретное число кластеров, дендрограмму "разрезают" горизонтальной линией на нужной высоте.

## Linkage (методы связывания): как измеряется расстояние между кластерами

Когда объединяются не отдельные объекты, а уже сформированные кластеры (группы объектов), нужно определить, что значит "расстояние между кластерами":

- **Single linkage** — минимальное расстояние между любой парой объектов из двух разных кластеров. Может создавать вытянутые, "цепочечные" кластеры (эффект "chaining").
- **Complete linkage** — максимальное расстояние между любой парой объектов из двух кластеров. Даёт более компактные, сферические кластеры.
- **Average linkage** — среднее расстояние между всеми парами объектов из двух кластеров. Компромисс между single и complete.
- **Ward linkage** — объединяет два кластера так, чтобы минимизировать прирост внутрикластерной дисперсии (похоже по духу на целевую функцию K-Means). Один из самых популярных методов на практике, обычно даёт сбалансированные, компактные кластеры.

## Python

```python
from scipy.cluster.hierarchy import dendrogram, linkage
from sklearn.cluster import AgglomerativeClustering
import numpy as np

X = np.array([[1,1],[1.5,2],[8,8],[9,9],[8.5,7]])

Z = linkage(X, method="ward")   # матрица связей для построения дендрограммы
# dendrogram(Z)  # визуализация в matplotlib

model = AgglomerativeClustering(n_clusters=2, linkage="ward")
labels = model.fit_predict(X)
print(labels)
```

## Плюсы / Минусы / Когда использовать

**Плюсы:** не нужно заранее знать $K$ (можно выбрать после построения дерева); дендрограмма даёт наглядное представление о структуре данных на разных уровнях детализации.

**Минусы:** вычислительно дороже K-Means (сложность обычно $O(n^2 \log n)$ или хуже) — плохо масштабируется на очень большие датасеты; после объединения кластеров "откатить" решение нельзя (жадный, необратимый процесс).

**Когда использовать:** небольшие-средние датасеты, когда полезна визуализация иерархической структуры (например, таксономия товаров, биологическая классификация), когда неясно заранее правильное число кластеров.

# DBSCAN (Density-Based Spatial Clustering of Applications with Noise)

## Интуиция

K-Means и Hierarchical Clustering предполагают, что кластеры имеют более-менее выпуклую, "компактную" форму. DBSCAN устроен принципиально иначе: он определяет кластеры как **плотно заполненные области**, разделённые областями низкой плотности — это позволяет находить кластеры **произвольной формы** (изогнутые, вложенные и т.д.) и, как побочный эффект, автоматически выделять объекты, не принадлежащие ни одному плотному региону, — то есть **выбросы**.

## Основные понятия

- **eps ($\varepsilon$)** — радиус окрестности вокруг каждой точки, в которой ищутся "соседи".
- **min_samples** — минимальное число точек (включая саму точку), которое должно находиться в радиусе `eps`, чтобы точка считалась **core point**.
- **Core point (базовая точка)** — точка, у которой в её `eps`-окрестности находится как минимум `min_samples` точек — такая точка находится в "плотной" части данных.
- **Border point (граничная точка)** — точка, у которой самой по себе соседей недостаточно для статуса core point, но она попадает в `eps`-окрестность какой-то core point — присоединяется к кластеру этой core point, но сама кластеры не "разрастает".
- **Noise (шум/выброс)** — точка, которая не является ни core point, ни border point — не попадает ни в одну плотную область — считается аномалией/выбросом.

## Как алгоритм работает

1. Для каждой точки посчитать число соседей в радиусе `eps`.
2. Отметить точки с достаточным числом соседей (≥ `min_samples`) как core points.
3. Объединить все core points, находящиеся в `eps`-окрестности друг друга, в один кластер (образуя цепочку связанных плотных точек).
4. Присоединить border points к соответствующему кластеру ближайшей core point.
5. Все оставшиеся точки, не попавшие ни в один кластер, помечаются как шум (noise/outliers).

**Почему DBSCAN находит кластеры сложной формы:** в отличие от K-Means, который оценивает "похожесть" через расстояние до единственного центроида, DBSCAN распространяет кластер **локально**, от точки к точке через цепочки плотных соседей — кластер может изгибаться, вытягиваться произвольным образом, лишь бы плотность точек вдоль этого пути оставалась высокой.

## K-Means vs DBSCAN

||K-Means|DBSCAN|
|---|---|---|
|Форма кластеров|Примерно выпуклая, сферическая|Произвольная|
|Нужно ли задавать число кластеров|Да ($K$)|Нет (определяется автоматически по плотности)|
|Обработка выбросов|Нет (все точки попадают в какой-то кластер)|Да (явно выделяет шум)|
|Чувствительность к масштабу|Высокая|Высокая (расстояния также используются)|
|Работа с кластерами разной плотности|Хорошо, если размеры схожи|Плохо — единые `eps`/`min_samples` не подходят для сильно разной плотности|

## Python

```python
from sklearn.cluster import DBSCAN
from sklearn.preprocessing import StandardScaler
import numpy as np

X = np.array([[1,1],[1.2,1.1],[0.9,1.3],[8,8],[8.2,7.9],[25,25]])  # последняя точка - явный выброс

X_scaled = StandardScaler().fit_transform(X)
model = DBSCAN(eps=0.5, min_samples=2)
labels = model.fit_predict(X_scaled)
print(labels)  # -1 обозначает шум/выброс
```

## Плюсы / Минусы / Когда использовать

**Плюсы:** не требует задания числа кластеров заранее; находит кластеры произвольной формы; автоматически выделяет выбросы.

**Минусы:** чувствителен к выбору `eps` и `min_samples` (неправильный выбор радикально меняет результат); плохо работает, когда кластеры имеют сильно разную плотность (единые `eps`/`min_samples` не подходят сразу для всех); менее эффективен в пространствах высокой размерности (снова curse of dimensionality влияет на понятие "плотности").

**Когда использовать:** данные с кластерами сложной, неправильной формы; когда явно нужно выделять выбросы как часть кластеризации; географические/пространственные данные.

# PCA (Principal Component Analysis)

## 1. Что решает алгоритм

PCA решает задачу **снижения размерности**: сжимает датасет с большим числом признаков $p$ в меньшее число новых признаков (**principal components**), сохраняя максимум исходной вариативности (информации) данных.

## 2. Интуиция

Представьте, что вы фотографируете 3D-объект (например, чайник) камерой — вы получаете плоское 2D-изображение, которое неизбежно теряет часть информации (глубину). Но если выбрать **удачный угол съёмки**, снимок сохранит гораздо больше узнаваемых деталей объекта, чем при неудачном ракурсе (например, "в лоб" на носик чайника, где почти ничего не видно). PCA делает математически то же самое: ищет наилучший "угол съёмки" — направления в пространстве признаков, вдоль которых данные **наиболее сильно варьируются** — и проецирует данные именно на эти направления, теряя как можно меньше информации при сжатии размерности.

## 3. Почему это работает математически

**Идея:** если два признака сильно коррелируют между собой (например, "площадь квартиры в м²" и "площадь квартиры в футах²"), они несут почти одну и ту же информацию — можно заменить их одним новым признаком без существенной потери информации. PCA обобщает эту идею: ищет **новые оси координат** (principal components), которые являются линейными комбинациями исходных признаков, повёрнутыми так, чтобы:

1. Первая ось (PC1) была направлена вдоль направления **максимальной дисперсии** данных.
2. Вторая ось (PC2) была перпендикулярна первой и направлена вдоль направления максимальной **оставшейся** (не объяснённой первой осью) дисперсии.
3. И так далее для последующих компонент.

Так как каждая следующая ось объясняет всё меньше оставшейся дисперсии, обычно можно отбросить последние компоненты (с малой дисперсией = малой информативностью), сохранив лишь первые несколько — и потерять при этом относительно немного полезной информации.

## Математическая последовательность PCA

### Шаг 1. Центрирование данных

Из каждого признака вычитается его среднее значение, чтобы данные были центрированы вокруг нуля:

$$X_{centered} = X - \bar{X}$$

Это необходимо, потому что PCA ищет направления **дисперсии**, а не абсолютного положения данных — центрирование убирает влияние смещения (сдвига) данных, оставляя только их "форму" разброса.

### Шаг 2. Расчёт covariance matrix (ковариационной матрицы)

$$\Sigma = \frac{1}{n-1}X_{centered}^T X_{centered}$$

Это уже знакомое нам из Части 1 понятие ковариации, но теперь посчитанное между **каждой парой признаков** и собранное в матрицу размером $p \times p$. Диагональные элементы — дисперсии отдельных признаков; недиагональные — ковариации между парами признаков.

### Шаг 3. Нахождение eigenvectors и eigenvalues ковариационной матрицы

Как объяснялось в Части 1, для матрицы $\Sigma$ находим такие векторы $\mathbf{v}$ (eigenvectors) и числа $\lambda$ (eigenvalues), что $\Sigma \mathbf{v} = \lambda \mathbf{v}$.

**Ключевой математический факт, на котором держится PCA:** eigenvectors ковариационной матрицы данных — это в точности те самые направления максимальной дисперсии, которые мы ищем, а соответствующие им eigenvalues показывают **величину** этой дисперсии вдоль каждого направления. Это не совпадение, а прямое следствие определений ковариационной матрицы и собственных векторов — доказывается через задачу оптимизации "найти направление, максимизирующее дисперсию проекции данных", решение которой аналитически сводится ровно к задаче нахождения собственного вектора с наибольшим собственным значением.

### Шаг 4. Выбор principal components

Сортируем eigenvectors по убыванию соответствующих им eigenvalues. Первый eigenvector (с наибольшим eigenvalue) — это **PC1 (первая главная компонента)**, второй — **PC2**, и так далее. Выбираем первые $k$ компонент, объясняющих достаточную долю суммарной дисперсии (например, 95%) — эта доля считается как $\frac{\sum_{i=1}^{k}\lambda_i}{\sum_{i=1}^{p}\lambda_i}$.

### Шаг 5. Projection (проекция)

Исходные данные проецируются на выбранные $k$ главных компонент через матричное умножение на матрицу из выбранных eigenvectors — получаем новый датасет с $k$ признаками ($k < p$) вместо исходных $p$.

## Небольшой числовой пример

Данные (два признака, уже центрированные):

|$x_1$|$x_2$|
|---|---|
|2|2.1|
|-1|-0.9|
|-1|-1.2|

Ковариационная матрица (упрощённо, приблизительно): признаки $x_1$ и $x_2$ почти идентичны и сильно положительно коррелируют (визуально данные лежат почти на прямой линии, направленной по диагонали "снизу-слева вверх-направо"). В этом случае первый eigenvector будет направлен примерно вдоль диагонали $(1,1)/\sqrt2$ — то есть вдоль направления, в котором данные варьируются больше всего, — а соответствующий eigenvalue окажется значительно больше eigenvalue второго компонента (перпендикулярного направления, где почти нет разброса). Если спроецировать данные только на PC1, мы почти не потеряем информацию — потому что почти вся дисперсия данных сосредоточена именно вдоль этого направления, а разброс в перпендикулярном направлении (PC2) минимален.

> **Важно.** Перед PCA признаки почти всегда нужно **стандартизировать** (привести к одному масштабу) — иначе признак с большим численным диапазоном (например, доход в рублях против возраста в годах) будет доминировать в ковариационной матрице просто из-за единиц измерения, а не из-за реальной вариативности данных.

## Python

```python
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler
import numpy as np

X = np.array([[2, 2.1], [-1, -0.9], [-1, -1.2], [1.5, 1.4], [-1.5, -1.4]])

X_scaled = StandardScaler().fit_transform(X)

pca = PCA(n_components=1)     # сжимаем 2 признака в 1
X_pca = pca.fit_transform(X_scaled)

print("Explained variance ratio:", pca.explained_variance_ratio_)  # доля объяснённой дисперсии
print("Principal components:", pca.components_)   # сами eigenvectors
print(X_pca)
```

**Пояснение:** `pca.explained_variance_ratio_` покажет, например, `[0.98]` — это значит, что первая главная компонента сохраняет 98% исходной вариативности данных, несмотря на то что мы сократили число признаков вдвое.

## Гиперпараметры и применение

|Параметр|Значение|Эффект|
|---|---|---|
|`n_components`|Число компонент для сохранения|Можно задать числом (например, 5) или долей объясняемой дисперсии (например, 0.95)|

**Зачем нужен PCA на практике:** визуализация многомерных данных (сжатие до 2-3 компонент для построения графика), ускорение обучения моделей на данных с большим числом признаков, борьба с мультиколлинеарностью (новые компоненты всегда некоррелированы между собой по построению), предварительная обработка данных перед кластеризацией или KNN (борьба с curse of dimensionality), сжатие изображений.

**Ограничения:** PCA находит только **линейные** комбинации признаков — если полезная структура данных нелинейна, PCA может её не уловить (для таких случаев существуют нелинейные аналоги, например, t-SNE, UMAP, Kernel PCA — выходят за рамки этого курса, но полезно знать об их существовании). Также после PCA новые компоненты — это абстрактные линейные комбинации исходных признаков, которые обычно **гораздо сложнее интерпретировать**, чем исходные признаки (это существенная плата за сжатие размерности).

# Anomaly Detection

## Isolation Forest

**Принцип:** строит ансамбль случайных деревьев решений, где каждое разбиение выбирает случайный признак и случайный порог. Интуиция: аномальные точки, будучи "редкими и другими", **изолируются (отделяются от остальных точек) за меньшее число случайных разбиений**, чем обычные, "нормальные" точки, находящиеся в плотных скоплениях. Средняя глубина, на которой объект оказывается изолирован по всем деревьям ансамбля, становится оценкой его "аномальности" — чем меньше средняя глубина, тем более аномальным считается объект.

**Область применения:** обнаружение мошенничества, дефектов оборудования, аномального сетевого трафика — особенно хорош при большом числе признаков и больших датасетах, так как не требует явного вычисления расстояний между всеми парами точек.

## One-Class SVM

**Принцип:** обобщение идеи SVM (Часть 4) на задачу с одним классом — вместо того чтобы разделять два класса, алгоритм строит границу, охватывающую область, где сосредоточено большинство "нормальных" данных, максимально плотно облегая эту область (с учётом допустимой доли выбросов, регулируемой гиперпараметром `nu`). Объекты, оказавшиеся **вне** этой границы, считаются аномалиями. Как и обычный SVM, может использовать kernel trick (обычно RBF) для построения нелинейной границы "нормальности".

**Область применения:** задачи, где аномалий очень мало или их нет вовсе в обучающих данных (обучение "только на нормальных примерах") — например, обнаружение дефектов на производстве, где брак встречается очень редко и не может быть достаточно представлен в обучающей выборке.

## Local Outlier Factor (LOF)

**Принцип:** оценивает аномальность объекта, сравнивая **локальную плотность** вокруг него с локальной плотностью его соседей. Объект считается аномальным, если плотность точек вокруг него значительно **ниже**, чем плотность вокруг его ближайших соседей — то есть объект находится в разреженной области относительно окружающего контекста. Ключевое преимущество LOF — учёт **локального**, а не глобального контекста: объект может быть нормальным в одной плотной области данных, но такая же удалённость от соседей в другой, изначально более разреженной области будет считаться нормальной, а не аномальной — LOF корректно обрабатывает данные с кластерами разной плотности (в отличие от, например, простого порога по расстоянию до ближайших соседей).

**Область применения:** данные, где "нормальная" плотность существенно различается в разных частях пространства признаков — например, разные сегменты клиентов с очень разным типичным поведением.

## Python (сводный пример)

```python
from sklearn.ensemble import IsolationForest
from sklearn.svm import OneClassSVM
from sklearn.neighbors import LocalOutlierFactor
import numpy as np

X = np.array([[1,1],[1.1,0.9],[0.9,1.1],[1,1.2],[15,15]])  # последняя точка - явная аномалия

iso = IsolationForest(contamination=0.2, random_state=42)
print("Isolation Forest:", iso.fit_predict(X))  # -1 = аномалия, 1 = норма

ocsvm = OneClassSVM(nu=0.2, kernel="rbf")
print("One-Class SVM:", ocsvm.fit_predict(X))

lof = LocalOutlierFactor(n_neighbors=2, contamination=0.2)
print("LOF:", lof.fit_predict(X))
```
