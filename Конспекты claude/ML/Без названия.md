# Decision Tree (Дерево решений)

## 1. Что решает алгоритм

Decision Tree решает задачи и классификации, и регрессии, разбивая пространство признаков на прямоугольные области через последовательность простых условий вида "признак $\leq$ значение?".

## 2. Интуиция

Представьте игру "20 вопросов": вы пытаетесь угадать объект, задавая последовательность вопросов типа "да/нет", каждый следующий вопрос зависит от ответа на предыдущий, и с каждым вопросом множество возможных вариантов сужается. Decision Tree делает то же самое с данными: на каждом шаге он выбирает признак и пороговое значение, которые **лучше всего разделяют** объекты на более "однородные" (по классам или значениям целевой переменной) группы, и повторяет это рекурсивно, пока не получит достаточно чистые конечные группы.

## 3. Терминология

- **Root (корень)** — самый первый узел, содержащий весь датасет.
- **Node (узел)** — точка разбиения, где проверяется условие по признаку.
- **Branch (ветвь)** — путь от узла к дочернему узлу, соответствующий результату проверки условия (да/нет).
- **Leaf (лист)** — конечный узел без дальнейших разбиений, содержащий итоговое предсказание.
- **Splitting (разбиение)** — процесс выбора признака и порога для разделения узла на два дочерних.
- **Recursive partitioning (рекурсивное разбиение)** — процесс повторного применения splitting к каждому дочернему узлу, пока не выполнится условие остановки.

## 4. Математическая идея: как выбирается лучший split

На каждом шаге алгоритм перебирает все признаки и все возможные пороги разбиения, и для каждого варианта считает, **насколько "чище" стали дочерние узлы** по сравнению с родительским. Для измерения "нечистоты" (impurity) узла в классификации используют Gini Impurity или Entropy.

### Gini Impurity

$$Gini = 1 - \sum_{i=1}^{K} p_i^2$$

**Разбор:**

- $K$ — число классов.
- $p_i$ — доля объектов класса $i$ в данном узле.
- Если узел полностью "чистый" (все объекты одного класса, $p_i=1$ для одного класса и 0 для остальных): $Gini = 1 - 1^2 = 0$ — минимальная нечистота.
- Если узел максимально "смешан" (например, при 2 классах поровну: $p_1=p_2=0.5$): $Gini = 1 - (0.5^2+0.5^2) = 1-0.5=0.5$ — для бинарного случая это максимум.

**Интуиция Gini:** это вероятность того, что если случайно выбрать объект из узла и случайно присвоить ему метку класса согласно распределению классов в узле, метка окажется неправильной. Чем ниже эта вероятность, тем "чище" узел.

### Entropy (энтропия)

$$H = -\sum_{i=1}^{K} p_i \log_2(p_i)$$

**Разбор:** аналогично Gini, измеряет неопределённость/смешанность узла, но через логарифм — понятие, заимствованное из теории информации (энтропия Шеннона), где $H$ показывает среднее количество бит, нужное для кодирования метки класса случайного объекта из узла. Чистый узел: $H=0$. Максимально смешанный бинарный узел ($p_1=p_2=0.5$): $H = -(0.5\log_2 0.5 + 0.5\log_2 0.5) = -(0.5\cdot(-1)+0.5\cdot(-1))=1$.

> **Важно.** Gini и Entropy на практике дают очень похожие деревья — Gini чуть быстрее вычисляется (нет логарифма), поэтому это дефолт в большинстве библиотек (включая sklearn). Принципиальной разницы в качестве обычно нет.

### Information Gain (прирост информации)

Показывает, насколько уменьшилась нечистота после разбиения узла на два дочерних:

$$IG = Impurity(\text{parent}) - \left(\frac{n_{left}}{n}Impurity(\text{left}) + \frac{n_{right}}{n}Impurity(\text{right})\right)$$

**Разбор:** мы вычисляем нечистоту родительского узла, затем — взвешенную (по числу объектов в каждой части) сумму нечистоты дочерних узлов, и вычитаем второе из первого. Алгоритм на каждом шаге выбирает **тот признак и тот порог, которые максимизируют Information Gain** — то есть дают наибольшее "очищение" данных.

Для регрессионных деревьев вместо Gini/Entropy используется снижение дисперсии (variance reduction) — аналогичная идея, но измеряется не "нечистота классов", а разброс значений целевой переменной внутри узла.

## 5. Дерево на небольшом датасете вручную

Датасет: решение о выдаче кредита по двум признакам.

|Доход (тыс.₽)|Возраст|Класс (вернёт кредит)|
|---|---|---|
|30|22|Нет|
|35|25|Нет|
|80|40|Да|
|90|45|Да|

Родительский узел: 2 "Да", 2 "Нет" → $p_{да}=0.5$, $p_{нет}=0.5$ → $Gini_{parent} = 1-(0.5^2+0.5^2)=0.5$.

Пробуем split по признаку "Доход $\leq 55$":

- Левая часть (Доход $\leq 55$): объекты 1, 2 — оба "Нет" → $Gini_{left}=1-(1^2+0^2)=0$
- Правая часть (Доход $> 55$): объекты 3, 4 — оба "Да" → $Gini_{right}=1-(1^2+0^2)=0$

$$IG = 0.5 - \left(\frac{2}{4}\cdot0 + \frac{2}{4}\cdot0\right) = 0.5 - 0 = 0.5$$

Это максимально возможный Information Gain (снизили нечистоту до нуля) — split по доходу с порогом 55 идеально разделяет классы, и дерево остановится на глубине 1 (оба дочерних узла уже чистые листья, дальнейшее разбиение не требуется).

## 6. Гиперпараметры и переобучение

Decision Tree, если ничем не ограничивать, будет расти, пока каждый лист не станет полностью чистым (даже если для этого нужно выделить лист под один-единственный объект) — это классический пример **overfitting**: дерево идеально "запоминает" обучающие данные, включая их шум, но плохо обобщается на новые данные.

|Гиперпараметр|Значение|Эффект|
|---|---|---|
|`max_depth`|Максимальная глубина дерева|Меньше → проще дерево, меньше overfitting, но риск underfitting|
|`min_samples_split`|Минимум объектов в узле для дальнейшего разбиения|Больше → дерево не будет делать разбиения на основе единичных примеров|
|`min_samples_leaf`|Минимум объектов в листе|Больше → более "усреднённые", устойчивые предсказания в листьях|
|`max_features`|Число признаков, рассматриваемых при каждом split|Меньше → больше разнообразия (важно для ансамблей, см. Random Forest)|

**Pruning (стрижка/обрезка дерева)** — альтернативный подход: сначала вырастить полное дерево, а затем обрезать (удалить) ветви, которые не дают существенного улучшения на валидационных данных — снижает overfitting постфактум, а не через ограничения во время роста.

> **Типичная ошибка новичка.** Оставлять `max_depth=None` (без ограничений) "для лучшего качества" — на обучающей выборке accuracy будет 100%, а на тестовой — заметно ниже. Всегда нужно ограничивать глубину или другие параметры и проверять на валидации.

## Python

```python
from sklearn.tree import DecisionTreeClassifier, plot_tree
import numpy as np

X = np.array([[30,22],[35,25],[80,40],[90,45]])
y = np.array(["Нет","Нет","Да","Да"])

model = DecisionTreeClassifier(criterion="gini", max_depth=3, min_samples_leaf=1)
model.fit(X, y)

print(model.predict([[60, 30]]))
print(model.feature_importances_)   # значимость каждого признака в разбиениях
```

## Плюсы / Минусы / Когда использовать

**Плюсы:** интуитивно понятен и легко визуализируется, не требует масштабирования признаков, естественно обрабатывает нелинейные зависимости и взаимодействия признаков, работает и с числовыми, и с категориальными признаками.

**Минусы:** высокая склонность к переобучению без ограничений, неустойчив — небольшое изменение данных может привести к совершенно другому дереву (высокий variance), не всегда точен по сравнению с ансамблями.

**Когда использовать:** нужна максимальная интерпретируемость (визуальное дерево решений понятно нетехническим людям), быстрый baseline, небольшие датасеты.

**Когда не использовать:** когда важна максимальная точность предсказания — в этом случае почти всегда лучше ансамбль деревьев (Random Forest, Gradient Boosting), а не одно дерево.

> **Запомни.** Одно дерево редко используют в продакшене само по себе именно из-за высокого variance — но оно является строительным блоком практически всех топовых табличных ML-алгоритмов (Random Forest, Gradient Boosting, XGBoost), которые разбираются далее.

# Random Forest

## 1. Что решает алгоритм

Random Forest — ансамблевый метод, решающий задачи классификации и регрессии через построение **множества** decision tree и объединение их предсказаний, что резко снижает переобучение, свойственное одиночному дереву.

## 2. Механика: Bagging + Random Feature Selection

Random Forest — это не просто "много деревьев". Ключевая идея — **специально сделать деревья разными (decorrelated)**, чтобы их ошибки компенсировали друг друга при усреднении.

### Bagging (Bootstrap Aggregating)

**Bootstrap sampling:** для каждого дерева в ансамбле создаётся своя обучающая выборка того же размера $n$, что и исходный датасет, но полученная **случайным выбором с возвращением (with replacement)** из исходных данных. Это значит, что в бутстреп-выборке некоторые объекты исходного датасета встретятся несколько раз, а некоторые — ни разу (в среднем около 37% объектов не попадают в конкретную бутстреп-выборку — это и есть **out-of-bag (OOB)** объекты для данного дерева).

Каждое дерево обучается на своей бутстреп-выборке — это уже вносит разнообразие между деревьями.

### Random feature selection

При каждом split в каждом дереве Random Forest рассматривает **не все** признаки, а только **случайное подмножество** из них (обычно $\sqrt{p}$ для классификации, $p/3$ для регрессии, где $p$ — общее число признаков). Это дополнительно "рассинхронизирует" деревья — без этого шага все деревья, скорее всего, делали бы очень похожие первые разбиения по самым сильным признакам и оказывались бы сильно коррелированы друг с другом.

### Voting / Averaging

Для классификации: итоговое предсказание — класс, набравший большинство голосов среди всех деревьев (voting), либо усреднение вероятностей. Для регрессии: итоговое предсказание — среднее значение предсказаний всех деревьев (averaging).

### Почему ансамбль работает лучше одного дерева

**Математическая интуиция.** Если у нас есть $M$ независимых (некоррелированных) моделей, каждая с дисперсией ошибки $\sigma^2$, то дисперсия их **среднего** равна $\sigma^2/M$ — усреднение резко снижает variance, оставляя bias практически неизменным. Одиночное дерево имеет высокий variance (нестабильно) при относительно низком bias (может выучить сложные зависимости) — Random Forest, усредняя множество разных деревьев, "гасит" именно variance, оставляя способность улавливать сложные закономерности.

> **Важно.** Если бы деревья были полностью одинаковыми (сильно коррелированы), усреднение бы почти не снижало variance. Именно поэтому и bootstrap sampling, и random feature selection критически важны — они делают деревья максимально независимыми друг от друга (decorrelation), что усиливает эффект усреднения.

## Feature Importance, Permutation Importance, OOB score

**Feature importance (стандартная):** для каждого признака суммируется, насколько сильно он уменьшал impurity (Gini/Entropy) во всех узлах всех деревьев, где использовался для split — признаки, часто дающие большой Information Gain, получают высокую важность.

> **Типичная ошибка новичка.** Стандартная feature importance в деревьях систематически завышает важность признаков с большим числом уникальных значений (например, непрерывные признаки против бинарных) — это известное искажение (bias), о котором нужно помнить.

**Permutation importance:** более надёжная альтернатива — для каждого признака его значения **случайно перемешиваются** (permutation) в тестовых данных, и измеряется, насколько сильно **упало качество** модели. Признаки, чьё "разрушение" сильно вредит качеству, — действительно важные; признаки, чья перестановка почти не влияет на качество, — малозначимые. Этот метод не имеет систематического смещения к типу признака.

**OOB score (out-of-bag score):** так как каждое дерево обучается только на своей бутстреп-выборке (~63% объектов), оставшиеся ~37% объектов ("out-of-bag") можно использовать для оценки качества этого конкретного дерева — фактически, это встроенная "бесплатная" валидация без необходимости выделять отдельную validation-выборку.

## Python

```python
from sklearn.ensemble import RandomForestClassifier
import numpy as np

X = np.array([[30,22],[35,25],[80,40],[90,45],[55,30],[65,35]])
y = np.array(["Нет","Нет","Да","Да","Нет","Да"])

model = RandomForestClassifier(
    n_estimators=200,     # число деревьев
    max_depth=5,
    max_features="sqrt",  # число признаков на split
    oob_score=True,
    random_state=42
)
model.fit(X, y)

print("OOB score:", model.oob_score_)
print("Feature importances:", model.feature_importances_)
print(model.predict([[60, 32]]))
```

## Важные гиперпараметры

|Параметр|Значение|Эффект|
|---|---|---|
|`n_estimators`|Число деревьев|Больше — обычно лучше и стабильнее (до определённого предела), но дольше обучение|
|`max_depth`|Глубина каждого дерева|Ограничивает сложность отдельных деревьев|
|`max_features`|Число признаков на split|Меньше → больше разнообразия деревьев, сильнее decorrelation|
|`min_samples_leaf`|Минимум объектов в листе|Больше → более устойчивые предсказания|

## Плюсы / Минусы / Когда использовать

**Плюсы:** значительно устойчивее к переобучению, чем одно дерево; хорошо работает "из коробки" с минимальной настройкой гиперпараметров; не требует масштабирования признаков; даёт feature importance; хорошо обрабатывает нелинейности и взаимодействия признаков.

**Минусы:** менее интерпретируем, чем одно дерево (нельзя визуализировать "весь ансамбль" так же наглядно); медленнее на предсказании, чем линейные модели; обычно уступает по точности хорошо настроенному Gradient Boosting на табличных данных; занимает больше памяти (нужно хранить много деревьев).

**Когда использовать:** сильный, надёжный baseline на табличных данных, когда не хочется тратить много времени на настройку гиперпараметров; когда важна умеренная интерпретируемость через feature importance.

# Gradient Boosting

## 1. Что решает алгоритм и идея

Gradient Boosting также строит ансамбль деревьев, но принципиально **иначе**, чем Random Forest.

### Чем Boosting отличается от Bagging

||Decision Tree|Random Forest (Bagging)|Gradient Boosting|
|---|---|---|---|
|Число базовых моделей|1|Много (независимых)|Много (последовательных)|
|Как строятся деревья|—|Параллельно, независимо друг от друга|**Последовательно**, каждое следующее исправляет ошибки предыдущих|
|Что уменьшает|—|Variance (за счёт усреднения)|Bias (за счёт последовательного улучшения)|
|Глубина отдельных деревьев|Может быть глубоким|Обычно глубокие|Обычно неглубокие ("weak learners", пни или мелкие деревья)|
|Риск переобучения|Высокий|Средний-низкий|Средний-высокий (нужно аккуратно настраивать)|

**Ключевая идея Boosting:** вместо того чтобы строить много независимых "сильных" деревьев и усреднять их (как в Bagging), Boosting строит последовательность **слабых** моделей (**weak learners** — обычно неглубокие деревья, "stumps"), где **каждая следующая модель специально обучается исправлять ошибки всех предыдущих**.

## 3. Математическая идея

### Residuals (остатки) и последовательное обучение

Идея в самом простом виде: обучаем первое дерево $h_1(x)$, предсказывающее $y$. Считаем остатки — то, что первое дерево ещё не смогло объяснить: $r_1 = y - h_1(x)$. Затем обучаем **второе** дерево $h_2(x)$, но уже не на исходный $y$, а на эти **остатки** $r_1$ — то есть второе дерево специализируется именно на том, что не смогло уловить первое. Третье дерево аналогично обучается на остатках после первых двух, и так далее.

### Формула ансамбля

$$F_m(x) = F_{m-1}(x) + \eta h_m(x)$$

**Разбор по элементам:**

- $F_{m-1}(x)$ — предсказание ансамбля из $m-1$ уже построенных деревьев (всё, что мы "накопили" до текущего шага).
- $h_m(x)$ — новое ("$m$-ное") дерево, обучаемое на текущих остатках/градиенте ошибки.
- $\eta$ (**learning rate**, он же shrinkage) — гиперпараметр, "ослабляющий" вклад каждого нового дерева — вместо того чтобы полностью доверять новому дереву, мы добавляем лишь небольшую его долю.
- $F_m(x)$ — обновлённый ансамбль после добавления $m$-го дерева.

**Почему это называется "Gradient" Boosting.** В общем виде (не только для MSE) на каждом шаге алгоритм считает не буквально остатки $y-\hat y$, а **отрицательный градиент функции потерь** по текущим предсказаниям — это обобщает подход на любую дифференцируемую функцию потерь (не только регрессионную MSE, но и log-loss для классификации и т.д.). Для MSE отрицательный градиент оказывается ровно равен обычным остаткам $y-\hat{y}$, поэтому в простейшем случае "остатки" и "градиент" — это одно и то же, но в общем виде Gradient Boosting — это **градиентный спуск в пространстве функций (моделей)**, а не в пространстве числовых параметров, как в линейной регрессии.

### Роль learning rate и числа деревьев

- Маленький $\eta$ (например, 0.01–0.1) заставляет каждое дерево вносить лишь небольшой вклад — это требует **большего числа деревьев (`n_estimators`)** для достижения того же качества, но обычно даёт более устойчивую, менее переобученную модель.
- Большой $\eta$ — модель обучается быстрее (нужно меньше деревьев), но выше риск переобучения и "перепрыгивания" через оптимум.

Между `learning_rate` и `n_estimators` есть классический компромисс: их часто подбирают вместе (уменьшая `learning_rate`, одновременно увеличивают `n_estimators`).

> **Типичная ошибка новичка.** Ставить большое `n_estimators` без early stopping — Gradient Boosting **может** переобучаться при слишком большом числе деревьев (в отличие от Random Forest, где больше деревьев почти всегда не хуже). Нужно обязательно отслеживать качество на валидации и использовать early stopping.

## Плюсы / Минусы / Когда использовать

**Плюсы:** как правило, даёт лучшую точность среди классических ML-алгоритмов на табличных данных; гибок — можно оптимизировать под разные функции потерь.

**Минусы:** склонен к переобучению без тщательной настройки (`learning_rate`, `max_depth`, `n_estimators`, регуляризация); обучается медленнее Random Forest (последовательный процесс, не распараллеливается по деревьям так же легко); чувствительнее к гиперпараметрам — требует более аккуратного тюнинга.

**Когда использовать:** нужна максимальная точность на структурированных/табличных данных, есть время на настройку гиперпараметров и кросс-валидацию.

# XGBoost / LightGBM / CatBoost

Это современные, высокооптимизированные реализации идеи Gradient Boosting, ставшие фактическим индустриальным стандартом для табличных данных.

## XGBoost (Extreme Gradient Boosting)

**Основная идея:** классический Gradient Boosting, но с добавлением **явной регуляризации** прямо в функцию потерь (штраф за сложность дерева — число листьев и величину значений в листьях), а также с использованием **вторых производных (Hessian)** функции потерь при построении каждого дерева (не только градиента, как в классическом Gradient Boosting), что делает оптимизацию точнее и быстрее сходящейся.

**Отличия от классического Gradient Boosting:** встроенная L1/L2-регуляризация деревьев; эффективная обработка пропущенных значений (модель сама учится, в какую сторону отправлять объекты с пропуском при split); поддержка параллелизации на уровне построения одного дерева (не самого бустинга, а поиска лучших splits); поддержка ранней остановки (early stopping).

**Гиперпараметры:** `n_estimators`, `learning_rate`, `max_depth`, `min_child_weight`, `subsample`, `colsample_bytree`, `reg_alpha` (L1), `reg_lambda` (L2), `gamma` (минимальный Information Gain для split).

**Когда использовать:** средние и большие табличные датасеты, когда важна точность и есть время на тюнинг; давно и хорошо себя зарекомендовал в соревнованиях (Kaggle).

## LightGBM (Light Gradient Boosting Machine)

**Основная идея:** оптимизация Gradient Boosting под **скорость и память** на очень больших датасетах, за счёт двух ключевых техник:

- **Leaf-wise growth (рост по листьям)** вместо level-wise (по уровням, как в XGBoost по умолчанию): вместо того чтобы разбивать все узлы одного уровня подряд, LightGBM всегда выбирает для разбиения тот **конкретный лист**, который даёт наибольшее снижение потерь, независимо от уровня — это даёт более быструю сходимость, но повышает риск переобучения на маленьких датасетах (поэтому важно контролировать `max_depth`/`num_leaves`).
- **Histogram-based splitting:** вместо перебора всех возможных порогов разбиения по непрерывным значениям признака, значения группируются в дискретные "бины" (гистограммы) — это радикально ускоряет поиск лучшего split.

**Отличия от XGBoost:** значительно быстрее на больших датасетах и при большом числе признаков; leaf-wise рост даёт потенциально более точные деревья при той же глубине, но требует аккуратной настройки, чтобы не переобучиться.

**Когда использовать:** очень большие датасеты (миллионы строк), большое число признаков, важна скорость обучения.

## CatBoost (Categorical Boosting)

**Основная идея:** Gradient Boosting, специально спроектированный для эффективной и качественной работы **с категориальными признаками** без ручного препроцессинга (one-hot encoding и т.п.).

**Почему CatBoost особенно удобен для categorical features.** Традиционный подход (one-hot encoding) плохо масштабируется при большом числе категорий (признак "город" с 500 уникальными значениями создаёт 500 новых бинарных столбцов). CatBoost использует технику **ordered target encoding** — каждой категории сопоставляется статистика по целевой переменной (например, средний target для этой категории), но вычисленная особым образом (используя только "предыдущие" по случайному порядку объекты), чтобы избежать **утечки данных (target leakage)**, которая возникла бы при наивном target encoding по всей обучающей выборке сразу.

CatBoost также использует **symmetric trees (симметричные деревья)** — на каждом уровне дерева используется одно и то же условие разбиения для всех узлов этого уровня, что ускоряет предсказание и действует как встроенная регуляризация.

**Отличия от XGBoost/LightGBM:** нативная и качественная обработка категориальных признаков; часто даёт хорошее качество "из коробки" с настройками по умолчанию, требуя меньше тюнинга; обычно немного медленнее LightGBM на чисто числовых данных.

**Когда использовать:** датасеты с большим количеством категориальных признаков (например, в e-commerce, рекламе — категории товаров, города, устройства), когда хочется хорошего результата с минимальной настройкой.

### Сравнительная таблица

|Model|Advantages|Disadvantages|Best use cases|
|---|---|---|---|
|**XGBoost**|Точность, регуляризация, зрелая экосистема|Медленнее LightGBM на больших данных|Средние датасеты, соревнования, когда нужна максимальная гибкость настройки|
|**LightGBM**|Очень быстрый, эффективен по памяти, хорош на больших данных|Риск переобучения при leaf-wise росте на малых данных|Очень большие датасеты, много признаков, ограничено время на обучение|
|**CatBoost**|Лучшая обработка категориальных признаков, мало тюнинга нужно|Может быть медленнее на чисто числовых данных|Данные с большим числом категориальных признаков|


# Support Vector Machine (SVM)

## 1. Что решает алгоритм

SVM решает задачи классификации (и, реже, регрессии — SVR), находя **оптимальную разделяющую границу** между классами — не просто любую границу, разделяющую классы, а ту, что оставляет **максимальный зазор** до ближайших точек каждого класса.

## 2. Интуиция

Представьте, что нужно провести дорогу между двумя районами города (классами), не задев ни одного дома. Можно провести множество вариантов дороги, которые технически не пересекают дома ни одного из районов, но SVM выбирает **самую широкую возможную дорогу** — то есть границу, максимально удалённую от ближайших "домов" (объектов) обоих классов. Именно эта широкая полоса делает границу более устойчивой к новым, ранее не виденным объектам.

## 3. Математическая идея

### Hyperplane (гиперплоскость)

Разделяющая граница задаётся уравнением:

$$\mathbf{w}^T\mathbf{x} + b = 0$$

- $\mathbf{w}$ — вектор весов, перпендикулярный гиперплоскости (задаёт её ориентацию).
- $\mathbf{x}$ — вектор признаков объекта.
- $b$ — смещение (bias), сдвигающее гиперплоскость от начала координат.

Это то же самое уравнение линейной decision boundary, что и в Logistic Regression — но SVM выбирает $\mathbf{w}$ и $b$ по другому критерию.

### Margin (зазор) и Support Vectors (опорные векторы)

**Margin** — расстояние от разделяющей гиперплоскости до ближайших объектов каждого класса. SVM максимизирует именно эту величину. Математически можно показать, что ширина зазора равна $\frac{2}{|\mathbf{w}|}$ — поэтому максимизация зазора эквивалентна **минимизации $|\mathbf{w}|$** при условии, что все объекты правильно классифицированы (лежат по нужную сторону от границы с достаточным отступом).

**Support Vectors (опорные векторы)** — объекты обучающей выборки, которые находятся **ровно на границе зазора** (ближе всего к разделяющей гиперплоскости). Это критически важное свойство SVM: итоговая граница определяется **только этими опорными объектами** — все остальные объекты, находящиеся дальше от границы, вообще не влияют на итоговое решение. Отсюда и название алгоритма.

### Soft margin и параметр C

В реальных данных классы редко разделяются идеально (без пересечений) — **soft margin SVM** допускает, что некоторые объекты могут оказаться внутри зазора или даже на неправильной стороне границы, но штрафует за это.

Гиперпараметр **$C$** контролирует баланс между шириной зазора и числом/величиной таких нарушений:

- **Большой $C$** — сильный штраф за нарушения → модель старается классифицировать все объекты правильно, зазор становится уже, риск переобучения выше.
- **Маленький $C$** — слабый штраф → модель допускает больше нарушений ради более широкого, устойчивого зазора, риск недообучения выше при слишком малом $C$.

### Kernel trick (ядерный трюк)

Многие реальные данные **линейно неразделимы** в исходном пространстве признаков. Kernel trick позволяет SVM находить нелинейные границы, **неявно** переводя данные в пространство более высокой размерности, где они становятся линейно разделимыми — без явного вычисления координат в этом новом пространстве (что было бы вычислительно очень дорого), а через вычисление функции ядра (kernel function), которая напрямую даёт результат скалярного произведения в этом новом пространстве.

- **Linear kernel** — без преобразования, обычная линейная граница.
- **Polynomial kernel** — соответствует переходу в пространство полиномиальных комбинаций признаков.
- **RBF kernel (Radial Basis Function, он же Gaussian kernel)** — наиболее популярное нелинейное ядро, позволяющее строить очень гибкие, "изогнутые" границы; имеет собственный гиперпараметр $\gamma$ (gamma), контролирующий "гибкость" границы (большой $\gamma$ → граница подстраивается под каждую точку локально → риск переобучения; маленький $\gamma$ → более гладкая, обобщённая граница).

## Плюсы / Минусы / Когда использовать

**Плюсы:** эффективен в пространствах высокой размерности; kernel trick даёт гибкость для нелинейных границ; решение определяется небольшим числом опорных векторов — компактное представление модели.

**Минусы:** плохо масштабируется на очень большие датасеты (классическое обучение SVM имеет сложность около $O(n^2)$–$O(n^3)$ по числу объектов); требует масштабирования признаков; выбор ядра и его гиперпараметров ($C$, $\gamma$) требует тюнинга и не всегда интуитивен; не выдаёт вероятности "из коробки" (нужны дополнительные вычисления, например, Platt scaling).

**Когда использовать:** средние по размеру датасеты, пространства высокой размерности (например, текстовые данные после векторизации), когда границы между классами сложные и нелинейные.

**Когда НЕ использовать:** очень большие датасеты (миллионы объектов) — Gradient Boosting или нейросети обычно масштабируются лучше.

## Python

```python
from sklearn.svm import SVC
from sklearn.preprocessing import StandardScaler
import numpy as np

X = np.array([[30,22],[35,25],[80,40],[90,45],[55,30],[60,33]])
y = np.array([0,0,1,1,0,1])

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)   # SVM требует масштабирования

model = SVC(kernel="rbf", C=1.0, gamma="scale")
model.fit(X_scaled, y)

print(model.predict(scaler.transform([[58, 31]])))
print("Число опорных векторов:", model.n_support_)
```

# Связь между алгоритмами (карта знаний)

```
Decision Tree
    ↓
Bagging (независимые деревья + усреднение)
    ↓
Random Forest

Decision Tree
    ↓
Boosting (последовательные деревья, исправляющие ошибки)
    ↓
Gradient Boosting
    ↓
XGBoost / LightGBM / CatBoost (оптимизированные реализации)
```

> **Запомни.** Random Forest снижает **variance** через усреднение множества независимых деревьев. Gradient Boosting снижает **bias** через последовательное исправление ошибок слабыми моделями. Это принципиально разные механизмы работы с ошибкой модели — и понимание этой разницы часто спрашивают на технических интервью.
